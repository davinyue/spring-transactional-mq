# 数据库迁移脚本规范化

## 背景

事务消息表当前通过全量建表脚本与人工选择升级脚本维护，缺少迁移版本、执行记录和校验能力；starter 还会在启动时自动建表并吞掉异常。

## 目标

将事务消息表脚本调整为可由 Flyway 执行的版本化迁移脚本，并取消 starter 的自动建表行为。

## 范围

- 为五种已支持数据库提供 V1 初始化和 V2 消费重试迁移脚本。
- 删除重复、未引用的建表脚本和 starter 自动建表实现。
- 更新演示配置、集成测试与 README 的接入说明。

## 非目标

- 不向组件引入 Flyway 依赖或自动执行 Flyway。
- 不实现 Liquibase changelog。
- 不在本次变更中执行真实数据库迁移。

## 关键设计

脚本按数据库类型隔离在 `db/migration/<database>` 目录，使用同一版本序列。业务工程将对应目录配置为 Flyway location；空库依次执行 V1、V2，已有库依据实际状态 baseline 到对应版本后继续迁移。

## 验收标准

- 五种数据库均具备 V1、V2 脚本。
- starter 不再注册或执行自动建表器。
- README 说明 Flyway 依赖、location 配置和已有库 baseline 方式。
- 相关单元测试通过。
