# 事务消息 Flyway 迁移隔离

## 背景

事务消息 starter 曾将专用 Flyway 注册为 Spring `Flyway` Bean，并使用默认历史表和默认脚本目录。这会使业务工程自身的 Flyway 迁移链退避或与事务消息脚本、版本号产生冲突。

## 目标

让事务消息和业务工程的 Flyway 迁移链独立共存。

## 范围

- 事务消息迁移使用非默认脚本目录和独立 schema history 表。
- starter 内部创建并执行事务消息 Flyway，不再暴露 `Flyway` Bean。
- 保留业务工程通过 `spring.flyway.*` 使用 Spring Boot Flyway 的能力。
- 更新测试与使用说明。

## 非目标

- 不修改业务工程已有 Flyway 脚本或历史表。
- 不引入未验证的达梦 Flyway 扩展。

## 关键设计

事务消息脚本迁移到 `transactionalmq/db/migration`，其初始化器使用 `txn_mq_flyway_schema_history` 记录版本；业务迁移继续使用 Spring Boot 默认 Flyway 配置。starter 仅在业务未显式配置时默认关闭 Spring Boot Flyway，避免仅引入 starter 即产生无关默认迁移。

## 验收标准

- [x] 事务消息迁移不会被 Spring Boot 默认 Flyway 扫描。
- [x] 事务消息迁移不会注册为 Spring `Flyway` Bean。
- [x] 业务工程设置 `spring.flyway.enabled=true` 后可保留自己的迁移链。
- [x] 相关测试与编译通过。
