# 事务消费者事务开启前钩子

## 背景

当前 Kafka 和 RabbitMQ 消费监听器会在 `required` 事务中执行消费幂等记录和消费者 `consume` 方法，消费者没有事务开启前的生命周期扩展点。部分业务需要在事务开启前完成上下文准备或非事务性预处理。

## 目标

- 为事务消息消费者提供事务开启前的执行钩子。
- 保证 Kafka 与 RabbitMQ 的执行顺序和异常处理语义一致。
- 保持已有消费者实现无需修改即可继续工作。

## 范围

- 扩展 `TransactionalMessageConsumer` 消费者接口。
- 调整 Kafka、RabbitMQ 消费调用器和监听器的调用顺序。
- 增加 API、Kafka、RabbitMQ 相关测试和使用说明。

## 非目标

- 不改变现有消费事务边界、幂等记录规则和重试策略。
- 不增加新的 MQ 类型或新的事务传播级别。
- 不将事务开启前钩子中的业务操作自动纳入事务。

## 关键设计

- 增加带默认空实现的 `beforeTransaction` 方法，参数与 `consume` 保持一致。
- 监听器在消息上下文和负载解析成功后调用 `beforeTransaction`，之后才进入 `TxnMqTransactionalService.required`。
- 钩子异常沿用现有消费失败流程；由于幂等记录在事务内，钩子异常不会创建消费幂等记录。
- 通过 MQ 专用消费调用器调用钩子，保持现有可替换调用器扩展点的一致性。

## 验收标准

- 未覆盖钩子的旧消费者可以正常编译并按原流程消费。
- 覆盖钩子的消费者在 `required` 事务执行前收到调用，且 `consume` 仍在事务回调内执行。
- 钩子异常会触发当前消费者配置的失败处理，不会执行 `consume` 或写入消费幂等记录。
- API、Kafka、RabbitMQ 相关测试通过，代码风格检查和 diff 检查通过。

## 风险与阻塞

- 钩子在事务外执行，其数据库写操作不会自动回滚；业务应仅放置明确需要事务外语义的逻辑。
- 钩子位于幂等判断前，重复投递或重试会再次执行，业务逻辑需要具备幂等或可重复执行能力。
